# Feature Specification: 桌面3D小宠物

**Feature Branch**: `001-desktop-3d-pet`  
**Created**: 2026-02-08  
**Status**: Draft  
**Input**: User description: "基于可行性报告创建桌面3D小宠物应用，选择方案A（Electron + Three.js）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 透明窗口3D宠物显示 (Priority: P1)

用户启动应用后，在桌面上看到一个可爱的3D小宠物，宠物浮在桌面上方，背景完全透明，不影响其他应用程序的使用。宠物会自动播放待机动画（如眨眼、摇尾巴、呼吸起伏等），让用户感受到宠物的"活力"。

**Why this priority**: 这是整个应用的核心视觉呈现，没有透明窗口和3D渲染，其他功能都无法展示。这是用户第一眼看到的功能，决定了产品的第一印象。

**Independent Test**: 可以通过启动应用、观察宠物是否正确显示在透明窗口中、动画是否流畅播放来独立测试。即使没有其他功能，这也是一个可展示的demo。

**Acceptance Scenarios**:

1. **Given** 应用未运行, **When** 用户启动应用, **Then** 在桌面上显示一个3D宠物，窗口背景透明，宠物置顶显示
2. **Given** 宠物正在显示, **When** 用户不进行任何操作超过3秒, **Then** 宠物自动播放待机动画（眨眼、呼吸、小动作）
3. **Given** 宠物正在显示, **When** 用户切换到其他应用窗口, **Then** 宠物保持置顶显示，不被其他窗口遮挡

---

### User Story 2 - 基础交互：拖拽与点击 (Priority: P2)

用户可以通过鼠标与宠物进行基础交互。用户可以点击宠物，宠物会做出反应（如开心跳跃、挥手）。用户可以拖拽宠物移动到桌面的任意位置。

**Why this priority**: 交互是让宠物"活起来"的关键。用户需要能够与宠物互动，而不是仅仅观看。这是用户参与感的基础。

**Independent Test**: 可以通过点击宠物观察反应动画、拖拽宠物观察位置变化来独立测试。

**Acceptance Scenarios**:

1. **Given** 宠物正在待机, **When** 用户单击宠物, **Then** 宠物播放反应动画（如开心跳跃或挥手），持续2-3秒后恢复待机
2. **Given** 宠物正在显示, **When** 用户按住鼠标左键并拖动, **Then** 宠物跟随鼠标移动到新位置
3. **Given** 用户正在拖拽宠物, **When** 用户释放鼠标, **Then** 宠物停留在新位置并恢复正常状态
4. **Given** 宠物正在显示, **When** 用户双击宠物, **Then** 打开对话/设置界面

---

### User Story 3 - AI智能对话 (Priority: P3)

用户可以与宠物进行自然语言对话。用户通过输入框输入文字，宠物通过AI（大语言模型）生成回复，并以可爱的方式展示给用户。宠物在思考和回复时会有相应的表情和动作变化。

**Why this priority**: AI对话是本项目的核心差异化功能，让宠物从"玩具"升级为"助手"。但需要在基础显示和交互完成后才能实现。

**Independent Test**: 可以通过打开对话界面、输入问题、观察AI回复和宠物动画来独立测试。

**Acceptance Scenarios**:

1. **Given** 对话界面已打开, **When** 用户输入问题并发送, **Then** 宠物播放"思考"动画，AI生成回复后显示在对话气泡中
2. **Given** 用户发送了问题, **When** AI正在生成回复, **Then** 宠物表现出思考状态（如挠头、看向上方），回复以流式方式逐字显示
3. **Given** AI回复完成, **When** 回复内容显示完毕, **Then** 宠物根据回复情感调整表情（开心、抱歉、好奇等），然后恢复待机
4. **Given** 对话界面已打开, **When** 网络不可用或AI服务异常, **Then** 显示友好的错误提示，宠物表现出困惑表情

---

### User Story 4 - 工作助手：提醒与快捷操作 (Priority: P4)

用户可以通过自然语言让宠物帮忙设置提醒、查询天气、打开应用程序等工作辅助功能。宠物会理解用户意图，执行相应操作，并给予反馈。

**Why this priority**: 工作助手功能让宠物具备实用价值，从"陪伴"扩展到"帮助"。需要在AI对话基础上实现。

**Independent Test**: 可以通过请求宠物设置提醒、查询天气、打开应用来独立测试各个工具功能。

**Acceptance Scenarios**:

1. **Given** 对话界面已打开, **When** 用户说"提醒我下午3点开会", **Then** 宠物确认创建提醒，到时间时通过系统通知提醒用户
2. **Given** 对话界面已打开, **When** 用户说"今天北京天气怎么样", **Then** 宠物查询天气API并以自然语言回复天气情况
3. **Given** 对话界面已打开, **When** 用户说"打开记事本", **Then** 宠物执行系统命令打开记事本应用
4. **Given** 用户设置了提醒, **When** 提醒时间到达, **Then** 显示系统通知，宠物播放提醒动画

---

### User Story 5 - 语音交互 (Priority: P5)

用户可以通过语音与宠物对话，宠物也可以通过语音回复用户。用户点击麦克风按钮开始语音输入，宠物会用可爱的声音回复。

**Why this priority**: 语音交互提升用户体验，让交互更自然，但需要在文字对话功能稳定后实现。

**Independent Test**: 可以通过点击麦克风、说话、听取宠物语音回复来独立测试。

**Acceptance Scenarios**:

1. **Given** 对话界面已打开, **When** 用户点击麦克风按钮并说话, **Then** 宠物播放"倾听"动画，语音被识别并显示为文字
2. **Given** 语音识别完成, **When** AI生成回复, **Then** 回复内容通过语音合成播放，同时显示文字
3. **Given** 用户正在语音输入, **When** 识别失败或超时, **Then** 显示友好提示，建议用户使用文字输入

---

### User Story 6 - 照片换肤（自定义宠物外观） (Priority: P6)

用户可以上传自己宠物的照片，系统自动识别宠物品种，生成对应的3D模型，实现"换肤"功能。用户可以将桌面宠物变成自己家宠物的样子。

**Why this priority**: 换肤功能大幅提升个性化体验和用户粘性，但技术复杂度高，需要在核心功能稳定后作为增强功能实现。

**Independent Test**: 可以通过上传照片、观察品种识别结果、查看生成的3D模型来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户打开换肤向导, **When** 用户上传宠物照片, **Then** 系统显示识别进度，完成后显示识别出的品种和置信度
2. **Given** 品种识别完成, **When** 用户确认品种正确, **Then** 系统开始生成3D模型，显示生成进度
3. **Given** 3D模型生成完成, **When** 用户预览模型, **Then** 可以查看模型的不同角度，并选择确认或重新生成
4. **Given** 用户确认新模型, **When** 应用新皮肤, **Then** 桌面宠物更换为新生成的模型，动画正常播放

---

### Edge Cases

- 当用户的显卡不支持WebGL时，显示友好的错误提示并建议系统要求
- 当AI服务响应超时（超过30秒）时，自动取消请求并提示用户重试
- 当用户在拖拽过程中将宠物拖出屏幕边界时，自动将宠物限制在屏幕可见范围内
- 当语音识别无法识别用户说的内容时，提供文字输入作为备选
- 当照片中包含多个宠物或无法识别的内容时，提示用户重新上传清晰的单只宠物照片
- 当本地LLM模型加载失败时，自动切换到云端API或提示用户检查配置
- 当系统托盘图标被误关闭时，提供从开始菜单重新启动的途径

## Requirements *(mandatory)*

### Functional Requirements

**核心渲染与显示**
- **FR-001**: 系统必须创建透明无边框窗口，背景完全透明，仅显示3D宠物内容
- **FR-002**: 系统必须支持窗口置顶显示，确保宠物始终可见
- **FR-003**: 系统必须使用Three.js渲染3D宠物模型，支持GLTF/GLB格式
- **FR-004**: 系统必须实现骨骼动画系统，支持10种动画状态：idle（待机）、thinking（思考）、happy（开心）、sad（难过）、confused（困惑）、drag（拖拽）、listening（倾听）、celebrating（庆祝）、sleepy（瞌睡）、curious（好奇）
- **FR-005**: 系统必须支持动画混合，实现动画状态之间的平滑过渡

**用户交互**
- **FR-006**: 系统必须支持鼠标点击检测（Raycasting），识别用户对宠物的点击
- **FR-007**: 系统必须支持宠物拖拽功能，用户可以移动宠物位置
- **FR-008**: 系统必须支持双击打开对话界面，默认显示为宠物旁气泡对话框，用户可在设置中切换为独立聊天窗口模式
- **FR-009**: 系统必须支持右键显示上下文菜单（设置、退出等选项）

**AI对话系统**
- **FR-010**: 系统必须支持多种AI模型接口（OpenAI、Claude、本地Ollama），当云端服务不可用时自动切换到本地Ollama，并实现常见问答的响应缓存以提升离线体验
- **FR-011**: 系统必须实现对话上下文管理，保持对话连贯性
- **FR-012**: 系统必须支持流式输出，实时显示AI回复内容
- **FR-013**: 系统必须根据AI回复内容调整宠物表情和动画
- **FR-014**: 系统必须支持对话历史的本地持久化存储

**工作助手功能**
- **FR-015**: 系统必须支持Function Calling机制，让AI调用本地工具
- **FR-016**: 系统必须实现提醒功能，支持定时和周期性提醒
- **FR-017**: 系统必须支持天气查询功能
- **FR-018**: 系统必须支持打开应用程序功能
- **FR-019**: 系统必须支持创建笔记功能

**语音交互**
- **FR-020**: 系统必须支持语音识别（STT），将用户语音转换为文字
- **FR-021**: 系统必须支持语音合成（TTS），将回复内容转换为语音播放

**换肤功能**
- **FR-022**: 系统必须支持用户上传宠物照片
- **FR-023**: 系统必须实现宠物品种识别功能
- **FR-024**: 系统必须支持图片转3D模型功能（本地TripoSR或云端Meshy API）
- **FR-025**: 系统必须实现自动骨骼绑定，使生成的模型可以使用预制动画

**系统功能**
- **FR-026**: 系统必须支持系统托盘图标，提供快捷操作入口
- **FR-027**: 系统必须支持开机自启动选项
- **FR-028**: 系统必须支持多显示器场景，记住宠物在指定显示器的位置
- **FR-029**: 系统必须提供设置界面，允许用户配置AI服务、宠物行为等选项

### Key Entities

> **存储方式**: 所有实体均使用SQLite本地数据库持久化存储

- **Pet（宠物）**: 3D宠物实体，包含模型数据、当前动画状态、位置坐标、情感状态
- **Conversation（对话）**: 对话会话实体，包含消息历史、上下文、关联的AI模型配置（SQLite存储）
- **Message（消息）**: 单条对话消息，包含角色（用户/助手/系统）、内容、时间戳（SQLite存储）
- **Reminder（提醒）**: 提醒实体，包含标题、触发时间、重复规则、完成状态（SQLite存储）
- **AIProvider（AI提供商）**: AI服务配置，包含API类型、模型名称、参数设置（SQLite存储）；API密钥通过系统凭证管理器安全存储
- **PetSkin（宠物皮肤）**: 自定义皮肤实体，包含原始照片、生成的3D模型、品种信息、骨骼绑定数据（模型文件存储在本地文件系统，元数据存储在SQLite）
- **UserSettings（用户设置）**: 用户偏好设置，包含窗口位置、AI配置、启动选项等（SQLite存储）

## Success Criteria *(mandatory)*

### Measurable Outcomes

**用户体验指标**
- **SC-001**: 应用启动到宠物显示的时间不超过5秒
- **SC-002**: 宠物渲染帧率在普通使用场景下保持30fps以上
- **SC-003**: 用户点击宠物后，反应动画在200ms内开始播放
- **SC-004**: 拖拽宠物时，移动响应延迟不超过50ms

**AI对话指标**
- **SC-005**: AI回复的首字符在用户发送后3秒内显示（网络正常情况下）
- **SC-006**: 对话上下文支持保持最近20轮对话记录
- **SC-007**: 90%的工作助手指令能被正确识别并执行

**语音交互指标**
- **SC-008**: 语音识别准确率在安静环境下达到90%以上
- **SC-009**: 语音合成的播放延迟不超过500ms

**换肤功能指标**
- **SC-010**: 宠物品种识别准确率对常见品种（猫、狗）达到85%以上
- **SC-011**: 本地3D模型生成时间不超过30秒（有GPU的情况下）
- **SC-012**: 生成的3D模型能正确绑定预制骨骼并播放动画

**系统稳定性指标**
- **SC-013**: 应用内存占用在空闲状态下不超过300MB
- **SC-014**: 应用在后台运行时CPU占用不超过5%
- **SC-015**: 应用支持连续运行24小时以上不崩溃

## Non-Functional Requirements

### 数据存储
- **NFR-001**: 系统必须使用SQLite作为本地持久化数据库，存储对话历史、用户设置、提醒等数据
- **NFR-002**: 数据库文件存储在用户应用数据目录（如 `%APPDATA%` 或 `~/Library/Application Support`）

### 安全性
- **NFR-003**: 系统必须使用操作系统凭证管理器安全存储API密钥（Windows Credential Manager/macOS Keychain/Linux libsecret）
- **NFR-004**: 禁止将API密钥以明文形式存储在配置文件或数据库中
- **NFR-005**: 应用更新必须通过HTTPS下载并验证签名

### 可观测性
- **NFR-006**: 系统必须使用electron-log记录本地日志，支持日志轮转和级别控制
- **NFR-007**: 系统必须集成Sentry进行崩溃报告和错误追踪（用户可选择是否启用）
- **NFR-008**: 日志和错误报告不得包含用户对话内容或敏感信息

### 最低系统要求
- **NFR-009**: 系统要求最低4GB RAM
- **NFR-010**: 系统要求支持WebGL2的显卡
- **NFR-011**: 支持的操作系统：Windows 10及以上、macOS 10.15 (Catalina)及以上、Ubuntu 20.04及以上

## AI Extension Architecture

本章节定义了桌面宠物应用的AI功能扩展架构，实现AI模块与宠物核心系统的松耦合集成。

### 设计原则

- **松耦合**：AI模块与宠物核心系统独立，通过抽象接口通信
- **可插拔**：每个AI能力可独立启用/禁用，不影响其他功能
- **事件驱动**：使用事件总线实现模块间异步通信
- **渐进增强**：基础宠物功能无AI时仍可独立运行

### 事件总线设计

事件总线是整个AI扩展架构的通信核心，实现模块间的异步解耦通信。

**核心特性**：
- **发布/订阅模式**：模块通过事件类型订阅和发布消息
- **优先级支持**：事件可设置优先级（LOW, NORMAL, HIGH, CRITICAL）
- **事件通道**：支持命名空间隔离，各模块可创建独立通道
- **类型安全**：完整的TypeScript类型定义，确保编译时类型检查

**预定义事件类型**：

| 事件类别 | 事件类型 | 说明 |
|---------|---------|------|
| 宠物事件 | `pet:state:changed` | 宠物状态变化 |
| 宠物事件 | `pet:action` | 宠物动作执行 |
| 宠物事件 | `pet:interaction` | 用户交互事件 |
| 宠物事件 | `pet:mood:changed` | 宠物情绪变化 |
| AI对话 | `ai:message:user` | 用户消息 |
| AI对话 | `ai:response:start` | AI响应开始 |
| AI对话 | `ai:response:chunk` | AI响应流式输出 |
| AI对话 | `ai:response:complete` | AI响应完成 |
| AI对话 | `ai:response:error` | AI响应错误 |
| 工具事件 | `tool:call:request` | 工具调用请求 |
| 工具事件 | `tool:call:result` | 工具执行结果 |
| 记忆事件 | `memory:store` | 记忆存储 |
| 记忆事件 | `memory:retrieve` | 记忆检索 |
| Agent事件 | `agent:task:start` | Agent任务开始 |
| Agent事件 | `agent:thinking` | Agent思考过程 |
| Agent事件 | `agent:action` | Agent执行动作 |
| Agent事件 | `agent:task:complete` | Agent任务完成 |
| MCP事件 | `mcp:server:connected` | MCP服务器连接 |

| 系统事件 | `system:error` | 错误事件 |

### 能力接口 (Capability/Trait)

能力接口定义了AI功能模块的标准化接口，支持能力的注册、管理和依赖解析。

#### 基础能力接口

所有能力必须实现 `ICapability` 基础接口：

```typescript
interface ICapability {
  readonly meta: CapabilityMeta;      // 能力元数据
  readonly status: CapabilityStatus;  // 当前状态
  initialize(): Promise<void>;        // 初始化
  dispose(): Promise<void>;           // 销毁
  healthCheck(): Promise<boolean>;    // 健康检查
}
```

#### 六种核心能力接口

| 能力类型 | 接口名称 | 说明 | 依赖 |
|---------|---------|------|------|
| 对话能力 | `IChatCapability` | 与LLM进行对话，支持流式输出、对话历史管理、系统提示词设置 | 无 |
| 记忆能力 | `IMemoryCapability` | 存储和检索记忆，支持语义搜索、命名空间隔离、TTL过期 | 无 |
| 工具能力 | `IToolsCapability` | 注册和执行工具，支持Function Calling机制 | 无 |
| Agent能力 | `IAgentCapability` | 执行多步骤任务，使用ReAct模式，支持任务进度订阅 | Chat, Tools, Memory |
| MCP能力 | `IMCPCapability` | 管理MCP服务器连接，支持stdio/sse/websocket传输 | 无 |
| Skills能力 | `ISkillsCapability` | 加载和执行预定义技能模板，支持触发词匹配 | Chat |

#### 能力注册与管理

能力注册表（`ICapabilityRegistry`）负责：
- 注册和注销能力实例
- 按依赖顺序初始化所有能力
- 提供能力查询和状态检查
- 等待特定能力就绪

### AI功能模块设计

#### MCP Manager（MCP服务器管理器）

管理Model Context Protocol服务器的连接和通信：

**功能**：
- 支持多种传输方式：stdio（子进程）、SSE、WebSocket
- 自动发现服务器提供的工具和资源
- 工具调用和资源访问的统一接口

**MCP服务器配置**：
```typescript
interface MCPServerConfig {
  name: string;                       // 服务器名称
  transport: 'stdio' | 'sse' | 'websocket';
  command?: string;                   // stdio模式命令
  args?: string[];                    // stdio模式参数
  url?: string;                       // sse/websocket模式URL
  env?: Record<string, string>;       // 环境变量
}
```

**默认包含的MCP服务器**：

应用开箱即用地包含以下MCP服务器，提供完整的助手体验：

| 服务器名称 | 功能 | 提供的工具 |
|-----------|------|-----------|
| `system-tools` | 系统工具 | 打开应用程序、执行系统命令、文件操作 |
| `reminder` | 提醒管理 | 创建提醒、编辑提醒、删除提醒、查询提醒 |
| `notes` | 笔记功能 | 创建笔记、搜索笔记、编辑笔记 |
| `weather-api` | 天气查询 | 查询天气、天气预报、空气质量 |
| `calendar` | 日历集成 | 查询日程、创建事件、提醒即将到来的事件 |

用户可在设置中禁用不需要的MCP服务器，或添加自定义MCP服务器扩展功能。

#### Skills Manager（技能系统管理器）

管理预定义的任务模板（技能）：

**功能**：
- 从技能目录扫描和加载技能定义
- 技能元数据管理（名称、描述、触发词、版本）
- 根据用户输入匹配合适的技能
- 执行技能并返回结果

**默认包含的技能**：

应用开箱即用地包含以下技能，覆盖常见助手场景：

| 技能名称 | 功能描述 | 触发词示例 |
|---------|---------|-----------|

| `reminder` | 提醒设置 | "提醒我下午3点开会"、"10分钟后提醒我"、"设置闹钟" |

#### Memory Manager（记忆系统管理器）

管理对话记忆和知识存储：

**功能**：
- 键值存储，支持命名空间隔离
- 可选的嵌入向量生成（用于语义搜索）
- 余弦相似度语义搜索
- TTL过期机制
- 持久化存储

**存储选项**：
```typescript
interface MemoryOptions {
  namespace?: string;                 // 命名空间
  ttl?: number;                       // 过期时间(ms)
  metadata?: Record<string, unknown>; // 元数据
  embed?: boolean;                    // 是否生成嵌入向量
}
```

#### Agent Manager（智能代理管理器）

执行复杂的多步骤任务：

**功能**：
- ReAct（Reasoning + Acting）模式
- 思考-行动-观察循环
- 任务进度订阅
- 任务取消支持
- 最大步骤限制

**执行流程**：
1. 接收任务目标和上下文
2. 构建系统提示词（包含可用工具列表）
3. 进入ReAct循环：
   - **思考**：分析当前状态，决定下一步
   - **行动**：调用工具执行操作
   - **观察**：获取工具执行结果
4. 达到最终答案或步骤上限时结束

### 与宠物系统集成

#### PetAIBridge（宠物-AI桥接器）

连接宠物核心系统与AI功能模块：

**职责**：
- 监听用户交互事件，转发给AI模块
- 监听AI响应，触发对应的宠物动作和表情
- 监听工具执行结果，更新宠物状态
- 简单的情感分析，根据AI回复内容调整宠物表情

**宠物动作映射**（基于10种动画状态）：
| AI状态/事件 | 动画状态 | 说明 |
|------------|---------|------|
| 收到用户消息 | thinking | 思考状态，如挠头、看向上方 |
| 等待语音输入 | listening | 倾听状态，如竖起耳朵、专注表情 |
| AI回复（积极/成功） | happy | 开心状态，如跳跃、挥手 |
| AI回复（消极/失败） | sad | 难过状态，如低头、耷拉耳朵 |
| AI回复（中性） | idle | 待机状态，如眨眼、呼吸起伏 |
| AI无法理解/出错 | confused | 困惑状态，如歪头、问号表情 |
| 用户拖拽宠物 | drag | 拖拽状态，如四肢摆动、悬空姿态 |
| 任务完成/目标达成 | celebrating | 庆祝状态，如欢呼、撒花 |
| 长时间无交互 | sleepy | 瞌睡状态，如打哈欠、眯眼、点头 |
| 发现新事物/收到新消息 | curious | 好奇状态，如睁大眼睛、探头 |

#### AIService（AI服务初始化器）

负责AI功能模块的生命周期管理：

**初始化流程**：
1. 注册MCP能力
2. 注册Skills能力
3. 注册Memory能力
4. 注册Agent能力
5. 初始化所有能力（按依赖顺序）
6. 初始化PetAIBridge

### AI扩展架构优势

1. **宠物核心功能无AI时仍可独立运行** - 渐进增强设计
2. **AI功能可按需加载，不影响启动性能** - 懒加载机制
3. **支持多种AI后端（OpenAI、Claude、Ollama）** - Provider抽象
4. **通过MCP协议扩展工具能力** - 标准化工具集成
5. **Skills系统提供预定义的任务模板** - 快速能力扩展
6. **Memory系统支持语义搜索和知识持久化** - 上下文记忆
7. **Agent系统支持复杂的多步骤任务执行** - 智能任务编排
